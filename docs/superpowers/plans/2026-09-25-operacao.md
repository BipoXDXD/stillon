# Vigilume — Plano 9: operação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deixar o dono operar o Vigilume sem SQL e sem gambiarra: sair de uma conta travada no segundo fator pelo terminal (`vigilume user reset-2fa`), trocar de celular sem desligar o 2FA (segredo pendente, pela API e pelo painel), pausar e retomar um canal barulhento sem perder a configuração (pela API e pelo painel), e rodar `--role=api` e `--role=prober` no mesmo host sem disputar a porta de métricas. Nenhum contrato atual muda: só entram rotas e campos novos.

**Architecture:** A troca de autenticador guarda o segredo novo numa coluna própria, `users.totp_pending_secret_enc`, cifrada com o mesmo `crypto.Box` e com a AAD amarrada à tabela, à coluna e ao usuário. O segredo antigo vale até a confirmação, que decifra o pendente e cifra de novo com a AAD de `totp_secret_enc`, numa transação que troca os códigos de recuperação e encerra as outras famílias. O SQL do `auth` continua escrito à mão (`internal/auth/totp_rotation.go`); o do `account` (o `reset-2fa`) e o do canal vão pelo `sqlc`. O `reset-2fa` é um serviço do `internal/account` (`ResetTwoFactor`) que o CLI só chama. Pausar é `ChannelService.SetEnabled` sob a RLS; o despacho já cancela avisos de canal desabilitado desde o Plano 3. O M7 é só a ordem de leitura no `config.Load` (o papel antes da porta de métricas) e uma dica na mensagem de porta ocupada. O painel reaproveita os componentes da ativação do 2FA e o `Confirmar` existente.

**Tech Stack:** Go 1.26, PostgreSQL 18 nos testes (17 e 18 na matriz do CI), `pgx/v5`, `sqlc` v1.31.1, `goose` v3, `testcontainers-go`. Painel: React 19, TypeScript 6, Vite 8, TanStack Query 5, `react-hook-form` + `zod`, Vitest 5, Playwright 1.63 com axe, `oxlint`.

**Spec:** `docs/superpowers/specs/2026-09-25-plano-9-operacao-design.md`. Onde este plano difere dela, a diferença está em "Desvios registrados em relação à spec aprovada", abaixo, e prevalece.

**Pendências absorvidas:** o grupo B ("Operação") do `docs/superpowers/PENDENCIAS-PARA-O-PLANO-9.md`, escolhido pelo usuário em 2026-09-25: recuperação do 2FA pelo CLI, troca de autenticador, rota para desabilitar canal e a porta de métricas em desenvolvimento (M7). A Tarefa 7 escreve o `PENDENCIAS-PARA-O-PLANO-10.md` com o resto (grupos C e D, o que depende do dono e os limites deste plano).

## Global Constraints

Valores copiados da spec e das decisões do usuário. Valem para todas as tarefas, inclusive as que não os repetem.

- **Go 1.26.** Módulo: `github.com/BipoXDXD/vigilume`. **PostgreSQL 18 nos testes** (`TEST_POSTGRES_IMAGE` troca a imagem); a matriz do CI roda 17 e 18.
- **Nenhum contrato atual muda.** Os shapes JSON, os códigos HTTP e os `error.code` existentes ficam como estão. Só entram estas rotas, com estes corpos e estas respostas:
  - `POST /api/v1/auth/totp/rotate`, atrás de `authn` e da família viva, corpo `{password, code}` (o `code` aceita também um código de recuperação; `recovery_code` é aceito como no `disable`): `200 {"otpauth_uri": "..."}`; `403 forbidden` com o 2FA desligado; `401 invalid_credentials` para senha errada, conta bloqueada, código errado ou ausente, e cada prova errada conta no bloqueio.
  - `POST /api/v1/auth/totp/rotate/confirm`, mesma cadeia, corpo `{code}` com o código do app **novo**: `200 {"recovery_codes": [10 strings]}`; `403 forbidden` sem troca em andamento; `401 invalid_credentials` para código errado (o pendente fica) ou conta bloqueada.
  - `PATCH /api/v1/channels/{id}`, atrás de `protegida` (o limitador comum), corpo `{"enabled": bool}`: `200` com o canal no formato de um item de `GET /channels`; `404 not_found` para canal alheio, inexistente ou id malformado; `400 validation_failed` para corpo inválido. Idempotente.
- **`401 unauthorized` fica só para token recusado** (ausente, inválido, vencido, de família morta). Senha errada, código errado e conta bloqueada são `401 invalid_credentials` (D24 do Plano 5), e o painel **não** renova a sessão num `invalid_credentials`.
- **Uma migration nova:** `00009_totp_pending_secret.sql`, `ALTER TABLE users ADD COLUMN totp_pending_secret_enc bytea;`, anulável e sem `DEFAULT`. Nenhuma tabela nova, nenhum `GRANT` novo. `users` continua sem RLS; o SQL novo do `auth` é escrito à mão (o R2 fica fora).
- **`vigilume user reset-2fa --email <e-mail>`**: só `--email` e a `DATABASE_URL`, sem senha; ordem `CheckRole` → `Migrate` → operação; saídas `0` (desligou, ou "nada mudou"), `4` (e-mail não cadastrado), `2` (uso), `1` (ambiente), `130` (interrupção), como o `set-password`.
- **Porta de métricas sem `METRICS_ADDR`:** `all` e `api` em `127.0.0.1:9090`, `prober` em `127.0.0.1:9091`. Com `METRICS_ADDR` definida (inclusive `off`), nada muda.
- **Textos em português**, no CLI, nas mensagens de erro e no painel. Os textos exatos estão nas tarefas e são comparados pelos testes.
- **`go test -race -count=1 ./...` verde ao fim de toda tarefa de backend**; `sqlc diff` limpo nas Tarefas 1, 2 e 3; no painel, `npm run typecheck`, `npm run lint` e `npm test` verdes ao fim das Tarefas 5 e 6.
- **Prova por sabotagem é obrigatória** para toda asserção de ausência e para todo teste que nasce verde. O implementador quebra a propriedade de propósito, vê o teste ficar vermelho **pela razão certa**, restaura (de backup, não por `git checkout`), e **registra no relatório** o que quebrou e o que viu. Sabotagem que não compila, ou que uma guarda redundante deixa sem efeito, não prova nada: a tabela diz quando isso acontece e qual variante prova. O teste vacuamente verde apareceu 14 vezes no Plano 1, 5 no Plano 2, 3 no Plano 4, uma no Plano 5 e uma no Plano 8.
- **Integração só com todos os jobs verdes no GitHub** (lint, secrets, test 17 e 18, web, image, e2e).

### Task 1: troca de autenticador com segredo pendente (API)

Spec §3.2 e §5. Trocar de celular deixa de exigir desativar e ativar de novo. `POST /auth/totp/rotate` prova a senha e o fator atual e grava o segredo novo em `users.totp_pending_secret_enc`, enquanto o antigo continua valendo; `POST /auth/totp/rotate/confirm` prova o app novo e, numa transação, promove o pendente, troca os códigos de recuperação, encerra as outras famílias e audita `totp.rotated`. O `disable` passa a limpar o pendente.

**Files:**
- Create: `internal/storage/migrations/00009_totp_pending_secret.sql`
- Create: `internal/auth/totp_rotation.go` (`StartRotation`, `ConfirmRotation`)
- Modify: `internal/auth/totp.go` (`ErrTOTPNoRotation`; helpers `aadAtivo`, `aadPendente`, `novaChave`, `novosCodigosDeRecuperacao` e `substituirCodigos` extraídos do `Enroll` e do `Confirm`; o `Disable` limpa o pendente)
- Modify: `internal/httpapi/totphandlers.go` (`TOTPRotate`, `TOTPRotateConfirm`)

// A confirmação toma a trava de sessões do usuário (D1 do Plano 5) antes de
// revogar as outras famílias: sem ela, uma rotação em curso deixaria o
// sucessor fora da revogação.
func TestConfirmRotationTakesTheUserLock(t *testing.T) {
	svc, pool, userID := setupTOTP(t)
	ctx := context.Background()
	familia := familiaViva(t, pool, userID, inicioDaTroca)
	novo := iniciarTroca(t, svc, pool, userID)

	conn, err := pool.Acquire(ctx)
	if err != nil {
		t.Fatal(err)
	}
	chave := "hashtextextended('vigilume.sessions:' || '" + userID.String() + "', 0)"
	var umaVez sync.Once
	soltar := func() {
		umaVez.Do(func() {
			if _, err := conn.Exec(ctx, `SELECT pg_advisory_unlock(`+chave+`)`); err != nil {
				t.Error(err)
			}
			conn.Release()
		})
	}
	t.Cleanup(soltar)
	if _, err := conn.Exec(ctx, `SELECT pg_advisory_lock(`+chave+`)`); err != nil {
		t.Fatal(err)
	}

	em := inicioDaTroca.Add(30 * time.Second)
	fim := make(chan error, 1)
	go func() {
		_, err := svc.ConfirmRotation(ctx, userID, familia, codigoEm(t, novo, em), em)
		fim <- err
	}()

	esperou := false
	for prazo := time.Now().Add(3 * time.Second); time.Now().Before(prazo); time.Sleep(10 * time.Millisecond) {
		var n int
		if err := pool.QueryRow(ctx,
			`SELECT count(*) FROM pg_stat_activity
			  WHERE datname = current_database() AND wait_event_type = 'Lock' AND wait_event = 'advisory'`).Scan(&n); err != nil {
			t.Fatal(err)
		}
		if n > 0 {
			esperou = true
			break
		}
	}
	soltar()
	err = <-fim
	if !esperou {
		t.Fatalf("a confirmação não esperou a trava do usuário (terminou com %v)", err)
	}
	if err != nil {
		t.Fatalf("a confirmação falhou depois de soltar a trava: %v", err)
	}
}

// A troca de autenticador com segredo pendente (Plano 9, §3.2). Antes dela,
// trocar de celular era desativar e ativar de novo, e no meio a conta ficava
// sem 2FA — quem desistisse no meio ficava desprotegido sem perceber.
//
// StartRotation grava o segredo do app novo em totp_pending_secret_enc, e o
// antigo continua valendo; ConfirmRotation, com um código do app novo, promove
// o pendente numa transação só. O pendente não tem prazo: só o confirma quem
// viu o QR, com uma sessão viva do dono. Cai na confirmação, no Disable, no
// reset-2fa do CLI e num novo StartRotation (que o substitui).

// StartRotation inicia a troca. O chamador já provou a senha
// (auth.CheckPassword); aqui se prova a posse do fator ATUAL, pelo código do
// app ou por um código de recuperação — as mesmas provas do Disable. Sem a
// segunda prova, uma sessão roubada somada à senha entregaria o segundo fator
// ao atacante, o bypass que o R38 fechou.
//
// A prova passa pelo Verify: o timestep do código do app fica consumido (o 2FA
// continua ligado depois deste passo, e o código observado não pode entrar
// depois), e o código de recuperação fica gasto com o rastro
// totp.recovery_used, mesmo que a troca nunca seja confirmada (R1 da spec).
//
// Devolve ErrTOTPNotEnrolled com o 2FA desligado e ErrTOTPInvalid com a prova
// errada ou vazia.
func (s *TOTP) StartRotation(ctx context.Context, userID uuid.UUID, email, code string, now time.Time) (string, error) {
	ligado, err := s.IsEnabled(ctx, userID)
	if err != nil {
		return "", err
	}
	if !ligado {
		return "", ErrTOTPNotEnrolled
	}
	if code == "" {
		return "", ErrTOTPInvalid
	}
	if err := s.Verify(ctx, userID, code, now); err != nil {
		return "", err
	}

	key, err := s.novaChave(email)
	if err != nil {
		return "", err
	}
	sealed, err := s.box.Seal([]byte(key.Secret()), aadPendente(userID))
	if err != nil {
		return "", fmt.Errorf("cifrar segredo TOTP pendente: %w", err)
	}
	// A guarda na WHERE, pelo motivo do R38: entre o Verify e o UPDATE cabe
	// uma desativação concorrente, e um pendente sem fator ativo seria lixo.
	tag, err := s.pool.Exec(ctx,
		`UPDATE users SET totp_pending_secret_enc = $2 WHERE id = $1 AND totp_confirmed_at IS NOT NULL`,
		userID, sealed)
	if err != nil {
		return "", fmt.Errorf("gravar segredo TOTP pendente: %w", err)
	}
	if tag.RowsAffected() == 0 {
		return "", ErrTOTPNotEnrolled
	}
	return key.URL(), nil
}

// ConfirmRotation conclui a troca com um código do app NOVO e devolve os 10
// códigos de recuperação novos. Numa transação só: o pendente vira o segredo
// atual (decifrado e cifrado de novo com a AAD de totp_secret_enc), o timestep
// usado fica consumido, os códigos antigos morrem, as OUTRAS famílias de
// sessão caem e a atual (familyID) fica, e a auditoria totp.rotated.
//
// Encerrar as outras sessões pelo mesmo motivo da troca de senha: um celular
// trocado pode ter sido perdido ou roubado.
//
// Devolve ErrTOTPNoRotation sem pendente (ou com o 2FA desligado),
// ErrTOTPInvalid com o código errado (o pendente fica) e ErrInvalidSession se
// a família caiu antes da trava.
func (s *TOTP) ConfirmRotation(ctx context.Context, userID, familyID uuid.UUID, code string, now time.Time) ([]string, error) {
	var pendente []byte
	var confirmado *time.Time
	err := s.pool.QueryRow(ctx,
		`SELECT totp_pending_secret_enc, totp_confirmed_at FROM users WHERE id = $1`, userID).
		Scan(&pendente, &confirmado)
	if errors.Is(err, pgx.ErrNoRows) {
		return nil, ErrNotFound
	}
	if err != nil {
		return nil, fmt.Errorf("carregar troca de TOTP: %w", err)
	}
	if len(pendente) == 0 || confirmado == nil {
		return nil, ErrTOTPNoRotation
	}
	plain, err := s.box.Open(pendente, aadPendente(userID))
	if err != nil {
		return nil, fmt.Errorf("decifrar segredo TOTP pendente: %w", err)
	}
	segredo := string(plain.Reveal())
	step, ok := validateTOTP(code, segredo, now)
	if !ok {
		return nil, ErrTOTPInvalid
	}

	if err != nil {
		return nil, fmt.Errorf("cifrar segredo TOTP: %w", err)
	}
	codes, err := novosCodigosDeRecuperacao()
	if err != nil {

	}

		return nil, fmt.Errorf("abrir transação: %w", err)

	// A trava de sessões do usuário ANTES de qualquer trava de linha (D1 do
	// Plano 5), na mesma ordem da troca de senha: trava, linha de users,
	// linhas de sessions. Sem ela, uma rotação de refresh em curso deixaria o
	// sucessor fora da revogação.
	if err := q.LockUserSessions(ctx, userID); err != nil {
		return nil, fmt.Errorf("travar sessões: %w", err)
	}

	// muda: o 200 sempre quer dizer "trocado, e a sessão atual continua viva".
	viva, err := q.FamilyIsLive(ctx, db.FamilyIsLiveParams{UserID: userID, FamilyID: familyID, Now: now})

		return nil, fmt.Errorf("conferir família de sessão: %w", err)
	}
	if !viva {
		return nil, ErrInvalidSession
	}

	// Compare-and-swap no pendente lido: um rotate que o substituiu, uma
	// confirmação concorrente ou um Disable no meio fazem a WHERE não casar,
	// e o código validado com o segredo velho não promove nada.
	tag, err := tx.Exec(ctx,
		`UPDATE users SET totp_secret_enc = $2, totp_pending_secret_enc = NULL, totp_last_timestep = $3
		   WHERE id = $1 AND totp_confirmed_at IS NOT NULL AND totp_pending_secret_enc = $4`,
		userID, ativo, step, pendente)
	if err != nil {
		return nil, fmt.Errorf("promover segredo TOTP: %w", err)
	}
	if tag.RowsAffected() == 0 {
		return nil, ErrTOTPNoRotation
	}
	if err := substituirCodigos(ctx, tx, userID, codes); err != nil {
		return nil, err
	}
	if _, err := q.RevokeOtherFamilies(ctx, db.RevokeOtherFamiliesParams{
		UserID: userID, KeepFamilyID: familyID, Now: now,
	}); err != nil {
		return nil, fmt.Errorf("revogar as outras sessões: %w", err)
	}
	// Trocar o segundo fator é o que um sequestro faria; o evento é a pista
	// do dono (a razão do R39).
	if err := insertAudit(ctx, tx, userID, "totp.rotated", nil, now); err != nil {
		return nil, err
	}
	if err := tx.Commit(ctx); err != nil {
		return nil, fmt.Errorf("confirmar troca de TOTP: %w", err)
	}
	return codes, nil
}

+		}
+		apierr.WriteError(w, r, apierr.CodeInvalidCredentials)
+	case errors.Is(err, auth.ErrInvalidSession):

+		apierr.WriteError(w, r, apierr.CodeUnauthorized)
